# Phase 10 验收清单：Jev 菜谱候选重排序离线实验

- **状态**：离线实验全部冻结流程已完成（2026-10-08）：30 场景真实评估、7 个边界检查、用户人工盲评与揭盲统计（净胜 13，出口 `continue`）。A1、B1–B4、C1–C6、D1–D4、E1–E3 有可复核证据；**A2、A3 保持未勾选**——账号实际价格与计费/最低充值条件无法核实，费用一律标注为估算。
- **依据与完整契约**：[Phase 10 实施清单](../implementation/phase-10-implementation.md#已确认实验契约)。使用 `@typesafe-ai/sdk`；仅离线模拟 AI 对话的搜索结果排序。
- **规格来源**：[GitHub Issue #14](https://github.com/jokerwon/shiguang/issues/14)（`ready-for-agent`）；标签不替代实施、付费执行授权或人工评审。
- **授权边界**：最终设计确认仅授权文档定稿，不授权安装依赖、付费调用或线上接入。
- **证据纪律**：每条勾选必须对应真实行为、命令输出、原始结果或人工评审证据。服务未调用、场景未完成或评审未提交时保持未勾选；不要把设计审阅、mock 结果或历史质量门当作实施验收。

## C. 排序与边界行为

| # | 场景 | 通过条件 |
|---|---|---|
| [x] C1 | 硬过滤与安全优先 | 时长/食材/菜系/标签/营养由代码先执行（实跑验证）；忌口命中与有过敏设置时成分信息不足均排除，且排序只对合格候选做置换——被排除候选不进入模型输入，模型无法恢复 |
| [x] C2 | 空候选、不足4道与矛盾需求 | 实跑：空候选 0 道且不发模型请求；不足 4 道如实返回 2 道，不凑数也不发模型请求（无法形成两组前 4 对照）；无优先级的矛盾需求标记「需要澄清」且不发模型请求；这些边界均不计入主评估净胜数 |
| [x] C3 | 每候选相同判断标准 | 开发样例 8 次真实调用：每次请求只含 1 个候选，并列返回资料充分性 Choice 与四级整体匹配 Score；响应无解释字段；四级标准自包含、不依赖编号或相邻等级 |
| [x] C4 | 资料不足与置信度 | 真实结果中 2 个候选判为「资料不足」（Score 1.65 / 1.22）→ 标为无法评价、后置但保留，未参与前 4；仅「资料足够」的 Score 参与排序；概率分布已落盘，未用于阈值判断 |
| [x] C5 | 排序优先级与完整性 | 真实结果可评价按 Score 降序 = 2.44 → 1.35 → 1.01 → 0.91，与落盘 `jevTop4` 一致；不变量检查 0 违规、候选 8 道不增不删不重复；最小必要回归见 `src/experiment/*.spec.ts` |
| [x] C6 | 服务失败与真实调用 | 8 次真实调用保留原始答案、概率分布、响应版本 `jev-1.13.0`、用量（8960/612 token）与耗时（421–953 ms）；官方版本名被代理拒绝时如实记为服务失败、未冒充 Jev 结果；模拟错误在记录中标记 `controlled` |
