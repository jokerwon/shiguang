# ADR-0008: 主题 —— AI 能力跃迁,分两 Phase 交付

- **状态**:已接受
- **日期**:2026-08-04
- **决策者**:Kai(经 grill 会话确认)

## 背景 (Context)

Phase 1 收齐后,应用具备:88 道菜谱、营养三要素、服务端用户数据、个性化推荐、AI 上下文注入、缺料购物清单。下一阶段有四个候选方向:规划闭环、社交与 UGC、AI 能力跃迁、内容质量与呈现。经 grill 会话拷问,选定**唯一主线:AI 能力跃迁**。

上一版 ADR-0006 明确「不实现 tool-calling Agent」,当时理由是用 20% 成本拿 80% 效果。但上下文注入的天花板已显:候选菜谱在 prompt 构建时一次性确定,AI 无法响应中途变更的条件,更无法替用户**动手**——用户在对话里说「我买了 2 斤牛腩」,还得自己去食材页手动添加。

## 决策 (Decision)

**下一阶段主题:AI 能力跃迁。核心价值场景:「动嘴不动手」**——AI 通过 tool-calling 直接查库、改 pantry、管收藏,用户在对话里一句话完成过去要跨多个页面的操作。

**分两 Phase 交付**:

**Phase 2(会动手)** — AI 从「顾问」变「代理」
- 持久化多会话(Conversation/Message 表,最小会话列表)(ADR-0010)
- 只读工具:查菜谱 / 查用户数据(ADR-0009)
- 写 pantry / 收藏:直接执行 + 消息内操作卡片可撤销(ADR-0009)
- 注入策略演进:偏好+pantry 保留注入,候选菜谱改为工具按需查询(修订 ADR-0006)
- 历史上下文:简单滑窗(最近 N 条)

**Phase 3(更懂你)** — 记忆的深度与安全
- 写偏好档案:前端确认卡片,显式确认才落库(ADR-0009)
- 滑窗 + 会话摘要:超长会话的上下文压缩(ADR-0010)
- 长会话种子脚本:快速构造 40+ 条会话,支撑摘要功能的验收走查(验收前置,见 [验收清单](../acceptance/phase-2-3-checklist.md) F3)
- 体验打磨

## 理由 (Rationale)

- 「动嘴不动手」是当前 UI 结构给不了的价值:跨页面操作(改 pantry→看匹配→收藏)被压缩成一句话,这是对话式交互的真正卖点。
- 已验证当前 `MODEL_NAME` 端点支持 function calling(含流式 tool_calls),技术前提成立,ADR-0006 当时的最大阻碍(架构不动)现在可以动。
- 先工具后记忆打磨:Phase 2 让 AI「会动手」即可感知;偏好档案写入(安全风险最高)和摘要机制(实现最微妙)放 Phase 3,风险后置。

## 备选方案 (Alternatives Considered)

- **规划闭环**(一周食谱/购物清单持久化/烹饪记录):是「下一个下一个」阶段的强候选,但需要先把 AI 工具链立起来(食谱规划天然是 AI + 写工具的场景),否后顺延。
- **社交与 UGC**:当前用户量撑不起内容生态,冷启动与审核成本高,否。
- **内容质量与呈现**(真图/烹饪模式/PWA):有价值但偏「打磨」,不构成阶段主线,可作为后续任何 Phase 的搭车项。

## 后果 (Consequences)

- 正面:对话从噱头变核心交互;为后续「规划闭环」奠定工具链基础。
- 负面:chat 架构大改(多轮 tool round-trip、流式 tool_calls、前端渲染工具过程);新增 Conversation/Message 存储;写工具带来确认 UX 与错误处理复杂度。
- 影响:ADR-0006 部分被修订(见 ADR-0009);需要新建会话相关表与列表 UI(见 ADR-0010)。
