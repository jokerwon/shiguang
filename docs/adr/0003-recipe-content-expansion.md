# ADR-0003: 菜谱内容扩充 —— 人工打底 + AI 批量生成,图片走占位符

- **状态**:已接受
- **日期**:2026-07-29
- **决策者**:Kai(经 grill 会话确认)

## 背景 (Context)

菜谱仅 12 道,需扩至 80–100 道以支撑个性化推荐。同时大部分菜谱 `img` 为空,卡片/详情页靠渐变占位符 + 菜名撑着;扩量后若仍无图,视觉上将是 100 个雷同的渐变方块。

## 决策 (Decision)

**内容扩充:A + B 混合**
- 人工手写/精选 20–30 道高质量菜谱打底(保证风格统一、字段完整)。
- AI 批量生成 50+ 道补量。

**AI 生成工作流**:一次性脚本 + 待审区 + 名称去重
- 提供 `pnpm recipes:generate` 脚本,按新 schema(含用量、营养三要素)调用 LLM 批量生成。
- 生成结果**先入待审区(JSON / staging),人工抽检 + 脚本校验(必填字段、营养合理性、名称去重)后再导入** Recipe 表,不直接入库。
- 营养三要素由 AI 估算,详情页标注"营养为估算值"。
- 不建常驻运营工具(一次性需求,不值得做成系统)。

**图片策略:纯占位符升级**
- 不做真图。升级占位符为"首字 + 菜系配色"的精致形式。
- 前端已有完善的 `onError` 占位符降级逻辑,直接复用。

## 理由 (Rationale)

- 人工打底保证"门面菜谱"质量与风格统一;AI 批量快速撑量,为推荐提供样本。
- 待审区 + 名称去重控制 AI 味的重复与低质;名称精确匹配 + 人工抽检足够,不上向量相似度。
- 图片:真图(AI 生成/开源图库)成本高、菜名对不准、风格杂;占位符升级零成本且规避"AI 味",与"内容深度优先"的资源分配一致。

## 备选方案 (Alternatives Considered)

- **数据导入(Recipe1M/爬取)**:清洗/字段对齐/版权是坑,质量参差。
- **UGC 用户上传**:冷启动难,需审核 + 图片上传,12 道菜阶段过早。
- **图片 AI 全量生成**:一次性成本 + 等待,非本版重点。
- **图片混合(头部真图)**:门面够亮但仍需图像管线,本版从简。

## 后果 (Consequences)

- 正面:菜谱量与质兼顾;图片零成本;生成质量可控。
- 负面:占位符视觉上限低于真图;AI 生成内容需人工把关,有运营成本;营养为估算值,精度有限。
