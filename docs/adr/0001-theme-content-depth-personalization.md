# ADR-0001: 下一版主题 —— 内容深度 + 个性化,分两个 Phase 交付

- **状态**:已接受
- **日期**:2026-07-29
- **决策者**:Kai(经 grill 会话确认)

## 背景 (Context)

食光当前为 MVP:12 道硬编码菜谱、AI 对话为无工具的纯文本生成(盲推)、收藏与食材清单仅存于浏览器 localStorage。下一版需在多个候选方向中确定战略主题,并控制交付范围。

候选主题:
- 内容深度 + 个性化
- 用户参与 + 留存(周计划/打卡/分享)
- UGC + 社区(用户上传/评分/关注)
- 后端加固 + 跨设备(数据同步/测试/监控)

## 决策 (Decision)

采用 **内容深度 + 个性化** 作为下一版主题。拆分为两个 Phase 交付:

- **Phase 1(地基)**:菜谱 schema 扩展 + 12 道老菜回填;新增 PantryItem / Favorite / UserPreference 三张表;收藏与食材清单从 localStorage 迁移到服务端。**不新增用户可见功能**,只立数据架构。
- **Phase 2(体验)**:扩充菜谱至 80–100 道;偏好设置页;个性化首页;缺料购物清单;AI 上下文注入;占位符视觉升级 + 详情页营养区块。

## 理由 (Rationale)

- 当前只有 12 道菜 + AI 盲推,核心循环(发现→做→存)最薄,加深加宽的杠杆最大。
- 数据层改动(#schema、#持久化)是高风险地基,单独落地验证,避免与新功能混在一起导致 bug 难以定位。

## 备选方案 (Alternatives Considered)

- **用户参与 + 留存**:12 道菜撑不起周计划,前提不足。
- **UGC + 社区**:冷启动难,需审核/图片上传,12 道菜 + 无用户基础时过早。
- **后端加固优先**:重要但不直接带来新功能价值,作为 Phase 1 的一部分顺带解决(持久化)。
- **单个 2.0 大版本一次发布**:回归风险高,地基与功能纠缠,否。

## 后果 (Consequences)

- 正面:核心体验质变;数据架构一次立起;风险分期可控。
- 负面:Phase 1 无用户可见价值,需对外说明;个性化依赖的数据(偏好/营养)需在 Phase 2 才完全生效。
