# Phase 10 实施清单：Jev 菜谱候选重排序离线实验

> **状态**：离线实验脚本已实施并通过全部不付费验证（2026-10-08）；开发样例已实跑真实服务（8 次请求，见下）。**30 个主场景的正式调用与用户人工盲评未发生**，付费执行规模与人工评审仍是外部前置。验收见 [Phase 10 验收清单](../acceptance/phase-10-checklist.md)。

**规格来源**：[GitHub Issue #14](https://github.com/jokerwon/shiguang/issues/14)（`ready-for-agent`）；离线实施已完成，付费执行与人工评审仍需满足授权前置。

## 目标与边界

验证 Jev 是否改善中文菜谱候选与本次需求的匹配程度。实验模拟 AI 对话的菜谱搜索结果排序，只评价候选重排序，不评价需求提取、聊天回复、推荐解释或首页推荐。

- 候选来自现有菜谱库，条件和安全约束由代码执行；不生成菜谱、不扩大候选范围、不放宽限制。术语见 [候选重排序](../glossary.md#候选重排序-candidate-reranking)。
- 两组复用同一个完整合格候选集，各取前 4 道；不按旧排序提前截断后再交给 Jev。
- 不替换共享 `rankRecipes`，不改在线 `search_recipes`、HTTP 契约、前端、数据库模型或现有聊天模型；不升级现有 AI SDK。
- 不采集真实用户请求、身份或历史聊天；使用人工中文场景和虚构偏好。
- 不增建评估平台、自动评审模型或新测试框架。后续实现沿用现有 TypeScript 脚本方式和 Jest 行为回归。
- 不新增 ADR：本次是可逆、与线上隔离的实验，不改变既有推荐与安全决策。将来若接入共享排序或改变第三方数据边界，另行评估并记录 ADR；不得借本清单覆盖 ADR-0009、ADR-0017、ADR-0018 或 ADR-0019。
- Phase 8 的未完成验收继续保留；本实验的安全边界检查不等于完成其他入口的全量安全验收。

## 关键前置发现

以下来自代码探索与官方正文，不是实验结果：

1. `apps/server/src/recipe/recommendation.scoring.ts` 的 `rankRecipes` 是纯函数，按时间适配、健康目标、每日轮换加权后截断；首页和 AI 搜索共用该事实源。现有排序没有模型调用，因此不能宣称引入 Jev 降低了排序模型成本。
2. `apps/server/src/chat/tools/read-tools-logic.ts` 的 `runSearchRecipes` 先执行食材全部包含、关键词、菜系、标签、营养和时长条件，再执行统一安全过滤、排序和截断。实验需要完整合格候选，不能将已截断的工具输出当作完整候选。
3. 同文件的 `SearchInput` 和 `apps/server/src/chat/tools/read-tools.ts` 的工具 schema 没有本次自然语言需求字段；人工场景必须在实验中另行提供需求，不声称在线工具已有该能力。
4. `toSummary` 仅返回精简资料，缺少原料和步骤；`apps/server/src/recipe/recipe.mapper.ts` 的 `toResponse` 已能从既有菜谱和关联行提供完整资料。实验复用已有数据映射，不补写推测事实。字段级事实以代码和 `apps/server/prisma/schema.prisma` 为准。
5. `apps/server/src/recipe/safety.ts` 的 `evaluateRecipeSafety` 与 `recipe-safety.service.ts` 是安全事实源。有过敏设置时，成分信息不足也要排除；语义评价的资料不足与安全判定的 `unknown` 是不同概念，前者不能使后者重新进入候选。
6. `apps/server/package.json` 的既有脚本使用 `tsx scripts/*.ts`，Node.js 要求为 >=20；本次确认前服务器未依赖 `@typesafe-ai/sdk`。实施时新增该 SDK，不引入另一套模型适配层。
7. [官方 JavaScript SDK](https://docs.typesafe.ai/sdk/javascript.md) 支持 `TypeSafeClient.systemOne()`，要求 Node.js >=20，凭证为 `TYPESAFE_API_KEY`。[API](https://docs.typesafe.ai/api.md) 支持独立 `Choice` 与 `Score` 问题；同一请求中的问题不能读取彼此的答案，由代码组合结果。
8. [官方模型页](https://docs.typesafe.ai/models.md) 在设计确认时列出 `jev-1.13.0`：输入 US$0.042/百万 token，输出免费；公开限速为 100K token/秒与 80 请求/秒，限速会动态调整。单请求总上下文为 64k token，state 加最长问题为 32k。执行前须重新核实，不把公开资料当作账号额度或充值条件的保证。
9. 同一模型页说明英文是主要训练语言，其他语言包括中文表现不等；英文重排序 cookbook 的收益不能外推到本实验。中文收益、稳定性、费用与延迟均尚未实测。

## 已确认实验契约

### 场景与对照

每个人工场景预先固定原始中文请求、明确硬条件、软偏好及其优先级、虚构偏好档案。两组使用相同硬过滤结果；不调用聊天模型分别提取条件。不把软偏好强行改成标签硬过滤。

冻结菜谱快照、完整候选集及初始顺序、虚构用户标识、时间、日期与轮换种子。基线保持现有算法；Jev 依据请求、必要的虚构偏好和候选事实判断，不额外奖励每日轮换。

模型与人工评审使用相同菜谱事实：名称、简介、菜系、标签、时长、营养、原料及步骤。不发送图片、真实用户信息或历史聊天，不生成口感或难度标签补齐证据。

### Jev 判断与排序

使用 `@typesafe-ai/sdk` 的 `TypeSafeClient.systemOne()`，固定 `jev-1.13.0`。每次只发送一个候选，使用固定判断标准，并列提问：

1. **资料充分性（Choice）**：资料足够评价主要偏好／资料不足／无法确定。后两者都标记为“无法评价”。这是模型判断，不是事实核查保证；保留概率分布供复核，不设未经评估的置信度阈值。
2. **整体匹配程度（Score）**：依据明确的主要和次要偏好，沿下列同一有序标准打分。只在资料足够时消费这个结果。

| 等级 | 独立、完整的情境定义 |
|---|---|
| 不匹配 | 已有事实明确支持菜谱与本次主要偏好冲突 |
| 部分匹配 | 已有事实支持满足部分偏好，但主要偏好仍有明显不足，且不属于与主要偏好明确冲突的情形 |
| 较匹配 | 已有事实支持满足主要偏好，但次要偏好有明确不足 |
| 高度匹配 | 已有事实支持满足主要及次要偏好，且没有明显冲突 |

标准直接写入问题和等级说明，不依赖等级编号、相邻等级或问题 ID 传递语义。不把多个独立维度打分后另加未确认权重。没有次要偏好时，不要求满足虚构的次要条件。

可评价候选按 Score 降序；无法评价候选后置但仍保留在合格候选中。同分或同为无法评价时沿用基线顺序。不生成解释，不把置信度当安全证明。明确时长、食材和安全限制始终在模型评价前执行。

### 评估与失败出口

- 主评估集为预先固定的 30 个中文场景，每个至少有 4 道合格候选；按预先固定的规则选取并记录，不能根据 Jev 输赢挑选场景。
- 场景覆盖疲惫省事、清淡但下饭、偏好有明确优先级、多道菜都合理等情况。无明确优先级的矛盾需求仅做“需要澄清”的边界检查，不让模型猜。
- 空候选、不足 4 道、安全排除、资料不足、矛盾需求另做边界检查，不计入主评估净胜数。空候选不调用 Jev，不凑数或放宽条件。
- 开发样例与正式评估分离；正式 30 场景开始前冻结模型、判断标准和排序规则，不用正式评估结果反复调参。保留原始答案、实际模型版本、用量和请求耗时。
- 由用户最终盲评：随机呈现匿名 A/B 前 4 列表，展示相同请求及菜谱事实，不展示模型分数、解释或排序来源；按需求满足程度记录 Jev 胜／平／负，难分高下记平。揭盲映射与评审材料分离。
- 服务失败单独记录，不计胜／平／负，不用旧排序冒充 Jev。未完成全部 30 场景或人工评审时，不宣称达到效果门槛。
- 硬约束违规为零是必要条件，任何违规直接判实验不通过；在完整评估与边界检查通过后，净胜数（胜数减负数）>=6 才继续接入设计。该门槛不是统计显著性结论，也不是上线授权。
- 效果结论仅适用于本次固定条件、中文场景和候选充足的排序环节，不外推到所有对话、需求提取或首页。

### 凭证、预算与执行授权

本次确认只授权文档定稿。安装依赖、准备运行工件与发起服务调用属于后续实施；付费执行须另获授权。

执行前核实 SDK 版本与重试行为、账号可用模型、实际价格、请求限制及计费/最低充值条件。凭证仅经服务端环境变量提供，不在聊天、日志、评审材料或版本库中泄露；不因 `.env.example` 未列凭证就认定账号没有凭证。

总调用预算为 US$10，覆盖开发样例、30 场景、边界检查和 SDK 重试。按真实请求体积及价格先估算，再记录实际用量和费用；核实并限制 SDK 重试造成的额外成本。无法核实预算或账号条件、预计超限、实际接近上限时暂停，不自动充值、增加预算、减候选或删证据。执行前估算不是已发生费用；未获账单或明确计费证据时，费用必须标明估算。
