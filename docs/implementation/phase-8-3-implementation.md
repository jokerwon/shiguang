# Phase 8-3 实施记录：按别名和分类发现食材

> 对应 [GitHub Issue #8](https://github.com/jokerwon/shiguang/issues/8)（父票 [#5](https://github.com/jokerwon/shiguang/issues/5)），依据 [ADR-0018](../adr/0018-ingredient-catalog-and-filtering.md)。#6 已交付名称／别名的**子串**检索；本票把「发现」收敛为**身份优先**：别名不被相近食材稀释，相近写法不冒充精确身份。

## 关键前置发现（来自真实代码与 live 数据库）

1. 既有列表搜索是 `name contains OR alias contains`：`keyword=番茄` 返回「番茄 / 番茄罐头 / 番茄酱」三条并列，别名与相近食材无法区分（livedb 复现）。
2. 既有 `resolveCandidates` 按整串等值匹配，但**全仓无调用方**（`fetchIngredientCandidates` 同样无人用），属死代码；本票以 `/ingredients/identify` 取代其位置，并删除该前端助手。
3. live 库 176 条已发布身份 / 99 条别名：别名唯一、别名不与任何规范名冲突、176 条 `rawNames` 零歧义——**当前数据不存在整串歧义**（`油` 无身份；`食用油` 与 `黄油` 是不同整串）。歧义分支因此以防御性测试覆盖，真实触发需先拆分「黑醋」这类合并身份。
4. `IngredientService` 的唯一调用路径是 `identifyIn` 纯函数（身份视图 + 词表），可零 DB 回归；与既有 `recipe-safety.service.spec.ts` 同样用 fake `PrismaService`。

### 代码审查后的修正（同轮，逐条复现）

独立审查（`ocr review`）提出 10 条后，以下按真实复现修正，其余按取舍保留：

1. **多词关键词查不到任何候选**（复现：`keyword=番茄 鸡蛋` → 0 条）：候选查询用整串子串匹配，而命中判定按词拆分。修复为先拆词、每个词各取子串候选取并集；实测 `keyword=番茄 鸡蛋` → 番茄 + 鸡蛋（`exactMatches=2`）。
2. **无关键词时 `exactMatches` 报成 176**：与「整串命中数量」契约不符。修复为 `keyword ? matched.length : 0`；实测浏览「全部」返回 `total=176, exactMatches=0`，页面标题仍为「食材」（相近候选提示改为仅在有搜索词时出现）。
3. **多词输入被误判为歧义**：`identifyIn` 汇总所有词，两个各自唯一的词会被当成歧义，而响应形状无法表达逐词映射。修复为按单一名词解析（取第一个非空词）；实测 `terms=番茄&terms=鸡蛋` → `matched=番茄`。
4. **解析失败被说成「没有完全同名」**：单独标记 `failed` 并提示「身份确认失败，无法判断…请稍后重试」，不再冒充无命中；浏览器阻断 `/ingredients/identify` 实测显示该文案。
5. **连续搜索的响应乱序**：加 `searchSeq` 守卫，只接受最后一次搜索的结果。
6. **解析请求全表 + 多查过敏原**：`identify` 改为 `select` 只取 id/名称/分类/别名。
7. **`terms[x]=y` 形态输入**：真实响应为 200 空结果（`ValidationPipe` 的 `whitelist` 会剥离嵌套键），不会 500；仍按防御加上字符串过滤与 `@IsOptional()`。
8. **嵌套三元与分号风格**：按审查建议改为 if/else 与统一分号。

未采纳：审查建议把「相近候选」标题限制为 `items.length > 0`；实测「相近候选」标题 + 「没有匹配的食材」并置在语义上仍准确（搜索无结果但确实存在相近项时才提示），不改。

## 遗留与边界

- **真实歧义触发场景**：当前库内不存在整串歧义（别名唯一、无别名与规范名冲突），列表页的候选区不会在现网数据上出现；其行为由 `identify.spec.ts` 的防御性用例锁定。若后续拆分「黑醋」这类合并身份（同时保留「黑醋」为别名），会立刻出现真实歧义。
- **未签名内容不改动**：本轮不动 `reviewedAt`、也不改任何资料条目（如把「食用油」补别名「油」），避免越权改变维护者未签字的内容判断。
- **`/ingredients/identify` 只做精确解析**：不含相似度排序与模糊纠错；子串候选仍由列表接口给出并由页面显式标注。
- **无 schema 变更**：本轮无迁移，`Ingredient`/`IngredientAlias` 结构不变。
