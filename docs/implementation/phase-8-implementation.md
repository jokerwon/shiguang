**规格来源**：[GitHub Issue #5](https://github.com/jokerwon/shiguang/issues/5)（`ready-for-agent`）；用户已确认复用既有 Jest 与真实应用冒烟的测试边界。

## 目标与边界

食材资料可查阅、别名可检索、菜谱可按全部所选食材筛选；身份与菜谱关联入库，维护者通过审核文件导入，图片沿用占位图。统一筛选、相关菜谱、首页 today/quick 和 AI 搜索的安全过滤；不恢复库存、匹配度或缺料。不增加主辅料字段、管理后台或 AI 百科工具。

## 关键前置发现

以下来自真实代码与既有验收工件，不是实现假设：

1. `apps/server/prisma/schema.prisma` 的 `Recipe.ingredients` 是自由文本 JSON，偏好的忌口／过敏原是自由文本集合；没有稳定食材身份和菜谱食材关联。
2. `apps/web/app/(screen)/filter/page.tsx` 只有菜系、标签、时间；既有 `useFilters` 以 localStorage 保存临时条件。食材页面需要建立，菜谱筛选页应扩展而非复制。
3. `apps/server/src/recipe/recipe.service.ts` 的列表查询先按普通条件分页和计数，不含食材和安全过滤；新增约束必须同时作用于结果与总数。
4. 同一 service 的 `findPersonalized` 中 today 使用推荐服务，quick 独立查询 `time <= 15`，未应用安全过滤。Phase 7 实施清单明确记录该缺口；本期“首页一致安全过滤”必须覆盖两者。
5. `apps/server/src/recipe/recommendation.scoring.ts` 依赖名称双向子串；`apps/server/src/chat/tools/read-tools-logic.ts` 使用单向关键词子串。它们不能表达稳定身份、多选全部包含和别名一致性。
6. 现有资料包含“番茄”“四季豆”“牛排（西冷或眼肉）”等别名、上位词及备选说明；禁止把截断括号当作可靠归一。
7. `apps/server/scripts/generate-recipes.ts` 生成 staging 内容，`apps/server/prisma/seed.ts` 在导入 curated/staging 时再次调用草稿校验、按菜谱名称 upsert。应延续审核和共用校验流程，不增加发布旁路。
8. 后端已有 `recommendation.scoring.spec.ts`、`recipe-draft.spec.ts`、chat 工具 `index.spec.ts` 的 Jest 行为测试；service 用显式 fake 依赖。没有真实 HTTP／DB e2e 套件。Phase 7 的真实 HTTP、SSE、浏览器和数据库恢复证据是可复用验收方式。
9. 用户已确认测试边界：真实应用外部入口为主，必要永久回归复用 Jest；不建设新的持久化 e2e 或组件测试框架。
